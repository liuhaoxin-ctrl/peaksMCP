Goal

Process the complete raw-PXT experiment so that the notebook contains one scientifically valid,
reviewable momentum-space result for every cut. Show every cut as a labeled panel in one compact
grid rather than emitting one output per cut. The notebook is the deliverable. Converted NetCDF
cache files are the only automatic disk artifacts permitted.

Definition of done

The task is DONE only when every cut's momentum-space result exists in a named live variable and is
rendered as an inline image in an executed notebook cell.
Exploration, planning, or reading the datasheet without producing those outputs does not
complete the task. Do not save processed NetCDF files or figures.

Work in two phases

1. Phase 1 - prepare: load and classify the experiment through the package's public experiment
   loader. If it reports missing validated NetCDF representations, convert the raw PXT input once
   and reload the experiment. Do not repeat conversion merely to test its cache.
2. Phase 2 - analyse: fit once, process every cut, render the results and append a closing summary.

  `datasheet.csv`, and do not probe objects with `dir`, `getattr`, `globals` or `__dict__`.
- Keep batch products in a dictionary keyed by exact scan stem. This is a stem-identifiable live
  variable; do not dynamically create globals for individual scans. End the single batch with

  ",".join(sorted(result_dict)))`, substituting the actual result-dictionary variable. Keep the

- Keep each code cell task-focused. Prefer one prepare/inventory cell, one gold-fit cell, one batch

Completion requirements

1. Build a complete inventory of the available records. Identify the gold reference, every cut,
   mappings, unsupported records, and classification conflicts before processing begins.
2. Derive the Fermi-level correction from the selected gold record during this trial. Fit the gold
   exactly once and reuse that correction for every cut; never use a remembered or hard-coded
   correction and never refit per cut.
3. Derive each cut's high-symmetry angular offset from the experiment metadata associated with that
   record. Do not guess it or substitute an unrelated metadata value.
4. Apply the Fermi correction, angular zeroing, and momentum conversion to every cut. Each final
   result must contain the full processed cut in momentum space, not a preview or centre slice -
   for a record whose file carries a scanned axis, select the plane rather than integrating it.
   Applying angular zeroing means calling the documented metadata assignment with that record's
   `theta_offset_deg` before `k_convert`; merely printing or mentioning the offset is not enough.
5. Keep every processed result in a clearly named live variable and render every final cut as an
   inline image. Never write a `*_processed.nc` product or an image file.
6. Leave clear before/after validation figures and binding-energy mapping slices in the notebook;
   inspect dimensions, coordinates and finite-data coverage before declaring success.
7. At the end, append one Markdown cell containing the selected gold and evidence, fitted Fermi
   correction, number of cuts processed, the variable/cell for every cut, cache conversion/reuse
   counts, every unprocessed target with its exact reason, and whether visual validation completed.
   Identify the selected gold explicitly as `gold=SELECTED_STEM (index SELECTED_INDEX)`, replacing
   both placeholders with the values observed in this run. Saying only "gold scan fitted once" is
   incomplete.
   Copy the complete `processed_stems=...` token returned by the batch receipt into this Markdown
   verbatim. Never construct the list from the processed count or assume consecutive scan numbers.
   State the observed numeric angular correction together with its exact source field, for example
   `theta_offset=VALUE deg from record.theta_offset_deg`, replacing VALUE with the observed number.
   Naming `record.theta_offset_deg` without its value is incomplete.

Operating constraints

- Preserve the input data. The notebook is an append-only execution record: add new work at the end
  and do not alter or delete earlier cells.
- The converted NetCDF cache and its metadata sidecar are the only allowed data writes. Do not call
  the persistence tool for analysis results and do not save figures.
- Keep notebook output bounded and decision-relevant. Do not dump complete arrays or metadata files.
- For a raw 3D mapping, do not call MDC before momentum conversion: the raw energy coordinate is
  kinetic energy. Pass `eV_slice=(binding_energy_center, total_width)` and the retained gold fit
  directly to `k_convert`, so Fermi correction happens before the narrow binding-energy slice and
  k-space interpolation. Do not convert several complete 3D mappings merely to make a view.
- If a mapping record has no angular reference in ExperimentIndex, do not invent zero degrees;
  skip that mapping view and state the missing metadata as its exact reason.
- Ask for scientific information only when it is genuinely absent from both the data and metadata.
  Make all ordinary workflow decisions yourself.
- Evaluation material is intentionally outside the workspace. Do not inspect benchmark source,
  evaluator directories, reference products, prior runs, or hidden answer keys. Use only the input,
  the active notebook, and the enabled agent tool surface.
